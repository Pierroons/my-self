# L'audit complet relit chaque commit : corriger un fichier ne retire pas ses
# versions antérieures de l'historique publié. Quand la décision est de ne pas
# le réécrire, ces versions-là sortent du compte, et elles seules.
#
# L'empreinte désigne un CONTENU, pas un chemin : toute modification en produit
# une autre, que l'audit relit. Une entrée ici ne masque donc aucune fuite à
# venir — ce que fait une exclusion par chemin dans opsec-allowlist.txt.
# Empreinte d'une version : git rev-parse <commit>:<chemin>
#
# Un message de commit s'accepte de même : l'empreinte du commit, et
# « (message) » à la place du chemin.
#
# Mêmes règles que l'allowlist : la raison nomme la nature de ce qui a été
# publié, jamais le texte, et l'audit relit ce fichier.

# l'inventaire du 03/10/2026. La décision est prise le 10/10/2026 : l'historique

# un secret mais une désignation interne, et une réécriture changerait tous les
# condensés postérieurs : les tags signés cesseraient de vérifier, les
# publications ne pointeraient plus sur rien, et chaque copie déjà clonée
# garderait de toute façon l'ancienne. Le coût est certain, le gain nul.
#

# être prise à l'envers faute de savoir qu'elle l'avait déjà été.
