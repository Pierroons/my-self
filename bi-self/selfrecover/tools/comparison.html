📊 SelfRecover — Comparatif sécurité

Trois façons de récupérer un compte, comparées côte à côte : le reset par e-mail habituel, et les deux formes de SelfRecover.

📄 Whitepaper SelfRecover 📄 Whitepaper SelfRecover-Lite 📦 GitHub
Pourquoi cette comparaison ? La récupération de compte par e-mail est souvent le maillon faible de l'authentification : qui lit la boîte obtient le compte. SelfRecover existe sous deux formes, pour deux types de site. SelfRecover retire l'e-mail de la récupération : il convient au site qui accepte de demander un secret à retenir. SelfRecover-Lite garde l'e-mail et exige une seconde preuve : il convient au site qui garde l'e-mail, une boutique en ligne par exemple.

Seul SelfRecover est implémenté. La colonne SelfRecover-Lite décrit une conception, publiée dans son whitepaper ; aucune implémentation n'en est publiée. Un ancien mode « Lite », montré en démonstration en v0.1.1 puis retiré le 18 août 2026, n'en partage ni le code ni le mécanisme.
Reset e-mail classique FRAGILE

Le parcours habituel. L'e-mail vaut preuve d'identité.

Flux

1. Le client clique « mot de passe oublié » 2. Le site génère un jeton 3. Un e-mail part avec un lien : site.fr/reset/{jeton} 4. Le client ouvre le lien 5. Le site demande un nouveau mot de passe → reset

Postulat

Quiconque a accès à l'e-mail du compte peut le récupérer.

→ E-mail lu par un autre = compte pris. Aucune seconde preuve.
SelfRecover-Lite CONCEPTION

Garde l'e-mail, et exige un appareil enregistré. Rien à retenir par défaut.

Flux

1. Le client clique « mot de passe oublié » 2. Un e-mail part avec un lien et un code 3. Le lien s'ouvre, ou le code se tape, sur un navigateur que le client a enregistré (le « témoin » : un secret aléatoire dans un cookie) 4. Le lien + le témoin → nouveau mot de passe 5. Sans appareil enregistré : le lien + un mot facultatif, ou un humain du service client, après un délai où le titulaire est prévenu 6. Une fenêtre de reprise (14 jours par défaut) : le titulaire dépossédé revient par un appareil d'avant

Postulat

L'e-mail seul ne suffit plus, l'appareil seul non plus : jamais l'un sans l'autre.

→ E-mail lu par un autre = insuffisant sans un appareil enregistré. Limite déclarée : le téléphone volé déverrouillé porte souvent le témoin et la boîte.
SelfRecover SANS E-MAIL

Aucun e-mail, aucun tiers. Split knowledge + diceware.

Flux

1. Niveau 1 : nom du compte + passphrase diceware (6 mots ou plus, tirés par le serveur ou aux dés) 2. Serveur la vérifie (Argon2id), rend un mot de passe et une passphrase neufs 3. Niveau 2 : un code papier + le mot mémorisé, dérivé en HMAC dans le navigateur 4. Niveau 3 : un arbitre humain lit des faits bruts

Postulat

Aucune dépendance externe. La récupération passe par ce que l'utilisateur détient, puis par un arbitre humain.

→ Zéro fournisseur d'envoi. Zéro tiers. Un accès root au serveur contourne tout le protocole.

📋 Quelle forme pour quel site

Le choix se fait une fois, avant l'installation, entre trois formes. Chacune porte ses propres facteurs de récupération et refuse ceux des autres ; un compte relève d'une seule.

  • clearweb · Lite (SelfRecover-Lite) : le site garde l'e-mail, et ses clients ne retiendront pas un secret de plus — une boutique en ligne, un service grand public.
  • clearweb · Standard (SelfRecover) : le site accepte de retirer l'e-mail de la récupération — un forum, une communauté, un public technique.
  • tor-onion (SelfRecover) : le service vit derrière un service caché. Lite n'y est pas proposé : un compte rattaché à une adresse e-mail est l'inverse de ce qu'on y cherche.

SelfRecover-Lite n'est pas une étape vers SelfRecover : c'est la forme qui convient au site qui garde l'e-mail.
